# 최종 구조 — AI 기반 사출공정 이상 탐지 및 검사 우선순위 지원 시스템

근거: `claude/분석로그_사출성형_CN7_RG3.md` (STEP 1~8, 15절까지)의 검증 결과 + KAMP 가이드북(출제 자료). 외부 데이터 없음.
원칙: 효과를 숫자로 만들지 않는다. 검증한 것과 검증하지 못한 것을 분리한다. ROC-AUC는 단독으로 쓰지 않고 항상 "사전예측 아님" 해석과 함께 쓴다.

## 0. 핵심 메시지 (한 문장)
본 데이터에서는 불량을 직접 사전예측하는 것보다, 공정변수로 설명 가능한 이상 운전 구간을 탐지하고 검사 우선순위를 지원하는 것이 검증 가능한 AI 적용 범위였으며, 설명되지 않는 불량은 억지로 정상 판정하지 않고 데이터 수집 개선 대상으로 분리하였다.

## 1. 과제 요구사항
- 대회 과제: 제조기업의 생산성 향상 및 작업환경 개선을 위한 아이디어를 제시하고 인공지능 알고리즘으로 구현. (공고문 원문 출처 확인 필요)
- 출제 배경: 최종검사 이전에 제조 이상 여부를 예측하는 AI 모델을 개발하고, 모델이 어떤 조건에서 정확하게 작동하고 어떤 조건에서 실패하는지 분석.
- 현장 이슈 (가이드북 p.16): 불량 과다 / 원인 분석 어려움·조치 시간 과다 / 문제 해결 지식의 자산화 부족 / Recipe 셋팅의 경험 의존.
- 장애 요인 (가이드북 p.16): 제품이 냉각·수축된 뒤에야 불량을 확인할 수 있어 불량 발생 시점에 공정을 멈추거나 제어하기 어렵다.
- 검사 방식 (가이드북 p.17): 각 물품을 검수자가 육안으로 양품 선별 → 사람 판단이라 품질 균일성 확보가 어려움.

## 2. 데이터에서 발견한 문제
1. 같은 입력에 다른 결과: 23개 공정변수가 완전히 같은 두 행에 서로 다른 PassOrFail이 붙는 구조가 반복됨 (공정변수는 공정조건 그룹 단위로 반복 기록, 라벨은 부품 단위). → 현재 공정변수만으로는 부품별 품질 결과를 결정하는 정보가 충분하지 않음.
2. 본 데이터에서 관찰된 불량 발생 패턴이 제품마다 다름:
   | | CN7 | RG3 |
   |---|---|---|
   | 불량 공정조건 그룹 위치 | 14개가 606개 중 24~60번째에 몰림 (전체의 6%) | 25개가 591개 중 68~566번째에 퍼짐 (전체의 84%) |
   | 연속 발생 | 11그룹 연속 | 없음 |
   | 요약 | 집중형 | 산재형 |
   (데이터에서 발견한 기술적 분류이며 표준 제조공정 분류가 아님)
3. 부품 단위 판별 능력은 확인되지 않음 — 불량 공정조건 그룹 중 한쪽 부품만 불량:
   - CN7: 11 / 14 = 78.6%
   - RG3: 25 / 25 = 100%
   (분모 = 불량이 1개 이상 나온 공정조건 그룹 수)

   그룹 내 결과 혼재 구조 전체 집계 (Target 재정의 근거):
   | | CN7 | RG3 |
   |---|---|---|
   | 전체 공정조건 그룹 | 606 | 591 |
   | 정상-정상 | 592 | 566 |
   | 한쪽만 불량 | 11 | 25 |
   | 양쪽 다 불량 | 3 | 0 |
   | 혼재율 (한쪽만 불량 / 전체 그룹) | 1.8% | 4.2% |
   | 불량 그룹 중 한쪽만 불량 (분모=불량 그룹) | 11/14 = 78.6% | 25/25 = 100% |
   전체 그룹 대비로 보면(분모=전체) 혼재율은 CN7 1.8%, RG3 4.2%. 불량이 1건 이상 나온 그룹만 보면(분모=불량 그룹) 한쪽만 불량인 비율은 CN7 78.6%, RG3 100%로, 동일 공정조건 내에서도 부품별 결과가 갈리는 사례가 대부분임. 두 관찰 모두 RG3에서 현재 공정변수로 신호를 못 찾은 것과 같은 방향 (인과 주장 아님).
4. 높은 구분 성능 ≠ 사전예측: CN7 반복 CV에서 높은 공정상태 구분 성능이 관찰되었으나, 시간축 검증에서 선행 신호 검정 207개 중 FDR 통과 0개. 성능의 상당 부분은 특정 운전 구간 식별에서 나온 것으로 보임.
5. 분석용 가공 과정에서 샷·부품·시간 식별자가 제거되어 위 구조가 숨겨져 있었음.

## 3. Target 재정의
### 3-1. 왜 바꿨나
- 같은 23개 공정변수(입력 X)에 정상/불량(출력 Y)이 함께 붙는 구조가 반복됨.
- 그래서 질문을 "이 부품이 불량인가?"에서 "이 공정조건에서 불량이 발생했는가?"로 바꿈.
- 모델 성능을 높이기 위한 조작이 아니라 데이터 생성 구조에 맞춘 문제 정의 변경. 실제로 Target을 바꿔도 CN7·RG3 성능은 거의 그대로였음.

### 3-2. 재정의 전후
| | 부품 Target (PassOrFail) | 공정조건 그룹 Target |
|---|---|---|
| 관측 단위 | 부품 | 동일 공정조건 그룹 |
| CN7 불량 | 17 / 1,211 | 14 / 606 |
| RG3 불량 | 25 / 1,182 | 25 / 591 |
| 문제 | 동일 입력에 상이한 라벨 | 공정변수 단위와 정렬 |
| 목적 | 부품 불량 판별 | 불량 발생 공정상태 탐지 |

### 3-3. 이름과 의미
- 발표 표기: "공정조건 그룹 불량 (ProcessGroup_Defect)" 또는 "불량 발생 공정조건 그룹". 코드·분석 로그의 변수명 Shot_Defect는 그대로 둠.
- 주석: 실제 Shot_Number는 확인하지 못함. 23개 공정변수가 같은 행 묶음을 Shot proxy로 정의.
- 정의: max(PassOrFail) = 해당 공정조건 그룹에서 최소 1개의 불량이 관찰되었는가. 공정 자체의 본질적 불량 상태를 정의한 것이 아니라, 관측된 결과를 공정조건 그룹 단위로 집계한 Target.
- PassOrFail은 폐기하지 않고 비교 기준으로 병기.
- 성격 규정: 이 Target은 "확정된 사실"이 아니라 "현재 데이터로 검증된 분석 가설"이다. 공정조건 그룹이 실제 Shot과 동일하다는 것은 Shot_Number가 없어 확인 불가. 표현 원칙: "동일한 23개 공정변수 조합이 반복 관측되고 그 안에서 부품별 결과가 달라지는 구조가 확인되었다"(⭕) / "한 Shot에서 LH·RH가 동시에 생산된다"(❌, 미확인 사실을 단정).

### 3-4. 재정의 다이어그램 (핵심 그림 1)
파일: `chart_target_redefinition.png`
흐름: 공정조건 그룹 A(23개 공정변수 값 동일) → 부품 1 정상(PassOrFail=0) / 부품 2 불량(PassOrFail=1) → 공정변수(입력)만으로는 부품별 결과(출력)를 구분할 정보가 부족함 → Target 재정의: "이 공정조건에서 불량이 1건이라도 발생했는가?" → 공정조건 그룹 Target: ProcessGroup_Defect = max(PassOrFail) (코드·로그 표기명: Shot_Defect).
발표 활용: 슬라이드 3(첫 번째 발견)에서 위쪽 절반(공정조건 그룹 A → 부품1/부품2)만 먼저 보여주고, 슬라이드 4(Target 재정의)에서 아래쪽 절반(문제 진술 → 재정의 → 최종 Target)을 이어서 공개하는 2단 리빌(reveal) 구성 권장.

## 4. AI 해결 아이디어
"불량을 100% 예측하는 AI"가 아니라 "검수자·작업자의 판단을 돕는 공정 상태 분류 AI".

공정조건 그룹 단위 공정 데이터 → AI 공정 상태 분석 →
- 정상 공정: 기존 검사
- 위험 공정 (과거 불량 집중 운전 조건과 유사): 우선 검사
- 다변량 공정 급변 감지 (보조 경보): 즉시 확인 — 불량 확정이 아님
- 공정변수 기반 판정 보류 (예: RG3): 현재 모델이 해당 제품의 불량을 설명할 근거를 확인하지 못함 → "정상"으로 표시하지 않음 → 기존 검사 유지 → 데이터 추가 수집 대상
→ 작업자 판단 지원

설계 포인트: "정상"과 "판정 보류"를 구분한다.

### 4-1. 왜 AI인가 (통계 분석과의 역할 구분)
- 통계 분석(EDA)이 한 일: 어떤 변수가 불량과 관련 있는지 확인 → 데이터 구조 발견 → Target 정의 → 모델 가능성 검증.
- AI가 하는 일: 새로운 공정 데이터가 들어올 때마다 학습된 위험조건과 비교해 위험점수를 계산하고, 위험 공정을 분류하고, 작업자에게 검사 우선순위를 제공.
- 한 줄: EDA는 문제를 정의했고, AI는 그 정의된 문제를 반복적으로 판정한다.

## 6. 생산성·작업환경 개선 — 효과의 크기가 아니라 효과가 발생하는 경로를 제시
관찰 사실 → 적용 가능성 → 실제 효과는 향후 검증, 의 3단 구조.
- 생산성 개선 경로: 위험·급변 공정조건을 우선 확인 → 이상 상황에 대한 대응 우선순위 제공 → 조치 지연 감소 가능성. (관찰 사실: CN7 불량이 연속 공정조건 그룹에서 발생 → 적용 가능성: 연속 불량 구간에서 이상 공정을 우선 확인 → 실제 효과: 미검증)
- 작업환경 개선 경로: AI가 공정 데이터 상시 모니터링을 맡고 작업자는 경보 상황 대응에 집중 → 반복 모니터링 부담 감소 가능성. 규칙 형태로 원인 인자를 보여줘 경험 의존 판단 보완.
- 지식 자산화: 불량이 몰렸던 운전 조건(설정 조합)을 기록으로 남김 → 현장 이슈 c·d 대응.
- 하지 않는 주장: 생산성·작업시간 X% 개선, 연속 불량 확산 억제 효과, 검사 생략·축소. 우선순위화는 검사 순서와 집중도를 바꾸는 것이고 전수 검사는 유지.
- 이유: 현재 데이터에 검사 소요시간, 작업자 수, 검사량, 경보 대응시간, 불량 유출 비용, 재작업 시간, 생산량, OEE가 없음. 증명한 것은 "생산성 향상 가능성이 있는 의사결정 구조를 제안했다"까지.

## 7. 모델이 작동하는 조건 / 실패하는 조건
- 핵심: 현재 공정변수는 부품별 판별보다 공정 상태의 이상 구간을 식별하는 데 더 적합하다. CN7은 불량이 특정 운전 구간에 집중되어 그 구간을 탐지할 수 있었지만, 동일 공정조건에서 부품별 결과가 갈리는 경우에는 판별력이 제한된다.
- 현재 데이터에서 확인된 작동 조건: CN7에서 불량이 특정 공정 상태에 집중된 경우 (특정 운전 구간, 샷 58~60 동시 급변).
- 실패하거나 확인되지 않은 조건:
  - 같은 공정조건에서 부품별 결과가 갈릴 때 (불량 공정조건 그룹 중 CN7 11/14, RG3 25/25)
  - 603~605: 동일 급변 패턴이 관찰되었으나 불량은 발생하지 않음 → 해당 패턴만으로 불량을 확정할 수 없음
  - 불량 전 예고가 필요할 때 (선행 신호 FDR 통과 0/207)
  - 다른 운전 기간으로 옮길 때 (불량 이벤트 1회라 검증 불가) — CN7 불량 14그룹 중 11개(78.6%)가 하나의 연속 운전 구간(50~60)에서 나옴. 즉 위험조건은 여러 독립적 불량 사례에서 반복 확인된 일반 규칙이라기보다 이 하나의 구간에서 관찰된 대표 조건에 가까움
- RG3 표현: "RG3 불량 원인 분석 실패"가 아니라 "RG3: 현재 공정변수에서 불량 구분 신호 미확인". 증명한 것은 현재 23개 변수·현재 데이터·현재 모델·현재 검증 방식에서 신호가 없었다는 것까지. 공정에 원인이 없다 / 캐비티가 원인이다 / 다른 센서가 있으면 설명된다는 증명하지 않음.

## 8. 한계 → 다음 데이터 요구사항
현재 프로젝트의 결함이 아니라 현재 데이터로 검증할 수 없는 영역. 숨기지 않고 다음 데이터 요구사항으로 연결.
| 검증하지 못한 것 | 필요한 데이터 |
|---|---|
| 사전예측, 선행 신호 | TimeStamp |
| 공정조건 그룹 = 실제 샷인지 | Shot_Number |
| 다른 기간 일반화, 운영 임계값 | 독립적인 미래 기간 라벨 데이터 |
| 급변 감지의 실제 precision/recall | 급변 발생 시점의 라벨 데이터 |
| RG3 부품별 차이, 쌍 안 위치 치우침 | PART_NAME(LH/RH), PART_FACT_SERIAL, 캐비티 식별자 |
| 생산성·작업환경 효과 | 검사시간, 작업시간, 경보 대응시간, 불량 유출 비용, 생산량 등 운영 데이터 |
- 데이터 설계 권고: 분석용 가공 시 Shot_Number, PART_NAME, PART_FACT_SERIAL, TimeStamp를 그룹 키로 보존.

## 10. 발표 흐름과 핵심 그림
- 흐름 (반전 구조): 최종검사 전에 불량을 예측하자 → 모델을 만들어보니 CN7 구분 성능이 높음 → EDA를 더 해보니 불량이 특정 구간에 몰려 있음 → 시간축으로 검증하니 선행 신호 0/207 → "불량을 미리 예측하는 모델"이 아니라 "공정 상태의 이상 구간을 탐지하는 모델"로 문제를 재정의.
- 핵심 메시지: 이 프로젝트는 모델 성능이 아니라, 제조 데이터의 구조에 맞는 AI 적용 범위를 찾아냈습니다. CN7에서는 공정 이상 구간 탐지, RG3에서는 판정 보류 및 데이터 개선으로 역할을 분리했습니다.

## 11. 발표 스토리 흐름 (최종안)
개정 이력: 이 절은 이전 버전(문제 제기 → 데이터 → 첫 번째 발견 → … 순서로 AI 모델 소개가 CN7 성능·반전보다 앞에 있던 12장 구성)을 대체한다. 변경 이유는 두 가지: (1) "AI를 어떻게 쓸 것인가"는 반전(사전예측 아님 확인) 다음에 나와야 설득력이 있다 — 반전 전에 시스템부터 보여주면 왜 4-state·판정보류 같은 조심스러운 설계를 했는지 이유가 늦게 나온다. (2) 개인 현장 경험 슬라이드는 이 팀 발표 구성에서 제외한다(발표자가 이 부분을 별도로 구성). 각 단계는 "목적 / 핵심 메시지 / 사용 자료 / 발표 포인트" 순으로 정리.

**1. 배경 — 왜 이 문제를 풀려고 했는가**
- 핵심 메시지: 사출성형 공정은 제품이 냉각·수축된 뒤에야 불량을 확인할 수 있어, 불량 발생 시점에 공정을 멈추거나 제어하기 어렵다. 검사도 검수자 육안 판별이라 품질 균일성 확보가 어렵고, 원인 분석·조치에 시간이 오래 걸린다.
- 사용 자료: 1절 (가이드북 p.16 현장 이슈·장애 요인, p.17 검사 방식)
- 발표 포인트: 아직 AI나 모델 이야기는 하지 않는다. "그래서 최종검사 이전에 이상을 미리 발견해야 한다"는 문제의식만 남기고 다음으로 넘어간다.

**2. 처음 목표 — 순진한(naive) 첫 접근**
- 핵심 메시지: 과제 요구를 그대로 해석하면 "공정 데이터로 최종검사 전에 불량 부품을 예측하자"가 자연스러운 첫 목표다. 그래서 처음에는 PassOrFail(부품 단위 정상/불량)을 Target으로 설정했다.
- 표현: 공정 데이터 → AI → 부품 정상/불량 (3단 흐름을 텍스트나 화살표 도형으로만 간단히 구성 — 별도 이미지 불필요)
- 사용 자료: 1절 출제 배경 문장, 2절 표(부품 Target CN7 17/1,211, RG3 25/1,182)
- 발표 포인트: 이 목표 자체가 틀렸다고 말하지 않는다. "이게 자연스러운 첫 접근이었다"는 톤으로, 다음 슬라이드의 반전을 위한 발판만 깔아둔다.

**3. 첫 번째 발견 — 모델을 만들기 전에 데이터부터 확인**
- 핵심 메시지: 모델을 바로 만들지 않고 데이터가 이 문제를 풀 수 있는 구조인지 먼저 확인했다. 그 결과, 23개 공정변수가 완전히 같은 두 행인데도 PassOrFail이 다른 경우가 반복적으로 나타났다 — 같은 입력에 다른 결과.
- 사용 자료: 2절 항목 1, `chart_target_redefinition.png` 상단 절반(공정조건 그룹 A → 부품1 정상 / 부품2 불량)만 노출
- 발표 포인트: 여기서는 결론을 내지 않고 "왜 이런 일이 가능한가?"라는 질문만 던지고 다음 슬라이드로 넘긴다.

**4. Target 재정의 — 표와 그림으로 증명**
- 핵심 메시지: 전체 공정조건 그룹 중 정상·불량이 혼재한 비율은 CN7 1.8%, RG3 4.2%(분모=전체 그룹). 불량이 1건 이상 나온 그룹만 보면(분모=불량 그룹) 한쪽만 불량인 비율은 CN7 11/14=78.6%, RG3 25/25=100% — 동일 공정조건 안에서도 부품별 결과가 갈리는 사례가 대부분. 따라서 질문을 "이 부품이 불량인가?"에서 "이 공정조건에서 불량이 발생했는가?"로 바꾸고, ProcessGroup_Defect = max(PassOrFail)로 재정의했다.
- 사용 자료: 15-1 혼재 구조 표(분석로그), `chart_target_redefinition.png` 전체 공개, 3-2 재정의 전후 비교표
- 발표 포인트: 표·그림이 주장을 대신하게 하고 말은 최소화한다. "왜 바꿨는지"는 다음 슬라이드에서 한 문장으로만 짚는다.

**5. "왜 바꿨는가" — 대조 문장 한 장**
- 핵심 메시지 (약한 표현 금지, 정확한 표현 사용): "모델 성능이 좋지 않아서 Target을 바꿨습니다"가 아니라 "모델 성능을 높이기 위해 Target을 바꾼 것이 아니라, 데이터의 관측 단위와 문제의 단위를 맞추기 위해 재정의했습니다." 실제로 Target을 바꿔도 CN7·RG3 성능은 거의 그대로였다는 사실이 이 문장의 증거.
- 사용 자료: 3-1절
- 발표 포인트: 슬라이드 하나를 통째로 이 대조 문장에만 쓴다 — 심사위원이 "혹시 성능 때문에 바꾼 건가?"라고 의심할 수 있는 지점을 먼저 차단한다.

**6. 재정의 후 검증 — CN7과 RG3는 다르게 반응한다**
- 핵심 메시지: 같은 방식으로 Target을 재정의했는데 두 제품의 불량 발생 패턴은 다르다 — CN7은 14개가 24~60번째에 몰림(집중형, 11그룹 연속), RG3는 25개가 전체의 84%에 퍼짐(산재형, 연속 없음).
- 사용 자료: 2절 항목 2 표, `chart_timeline.png` (CN7 위험영역+불량 위치), 필요 시 `chart4_rg3_grid.png` (RG3 분산 보조자료)
- 발표 포인트: "집중형/산재형"은 데이터에서 발견한 기술적 분류이지 표준 제조공정 용어가 아니라고 각주로 명시. 이 차이가 이후 CN7과 RG3의 AI 적용 방식이 갈리는 이유임을 암시만 하고 넘어간다.

**7. 모델 성능 — 숫자를 먼저 보여준다**
- 핵심 메시지: CN7 공정조건 그룹 단위, Group CV 기준 DT depth=2 규칙(Plasticizing_Position>1.44 AND Clamp_Close_Time>0.04) ROC-AUC 0.904 / Recall 0.89 / Precision 0.21. LogReg ROC-AUC 0.947 / PR-AUC 0.463(무작위 기준 0.023).
- 사용 자료: 5절 표 1~2행, `chart6_model_comparison.png`, `chart8_cn7_importance.png`
- 발표 포인트: 숫자를 자신 있게 제시하되 "같은 운전 기간 안에서만 검증"이라는 조건을 화면에 같이 둔다 — 다음 슬라이드 반전의 복선을 깐다.

**8. 반전 — 이것이 사전예측인가?**
- 핵심 메시지: 큰 글씨로 "높은 모델 성능 = 사전예측 성공인가?"를 질문으로 던진다. 시간축 선행 신호 검정(207개, BH-FDR)을 했더니 통과한 것이 0개였다. 즉 모델은 "불량을 미리 안다"가 아니라 "불량이 몰린 운전 구간을 알아본다"였다.
- 사용 자료: 2절 항목 4, 10절 흐름, `chart_step7_zoom.png` (58~60 양쪽불량 vs 603~605 동일 패턴·불량 없음)
- 발표 포인트: 발표에서 가장 힘을 줘야 하는 슬라이드. "우리가 세운 가설을 스스로 검증해서 바로잡았다"는 서사로 전달 — 이 프로젝트의 핵심 메시지("모델 성능이 아니라, 제조 데이터의 구조에 맞는 AI 적용 범위를 찾아냈다")가 여기서 처음 등장한다.

**9. 그래서 AI를 어떻게 쓸 것인가 — 공정 상태 모니터링**
- 핵심 메시지: 부품 불량을 직접 확정하는 AI가 아니라, 공정 상태를 감시하고 검사 우선순위를 지원하는 AI로 목적을 바꾼다. 정상(기존 검사) / 위험(우선 검사) / 급변(즉시 확인, 불량 확정 아님) / 판정보류(RG3, 데이터 추가 수집 대상)의 4-state 구조. "정상"과 "판정 보류"를 구분하는 것이 설계의 핵심.
- 사용 자료: 4절, 4-1절
- 발표 포인트: 이 슬라이드가 8번 반전 바로 다음에 나오는 이유를 분명히 한다 — "사전예측이 안 되기 때문에 시스템을 이렇게 설계했다"는 인과관계를 말로 짚는다.

**10. 실제 작동 화면**
- 핵심 메시지: 9번에서 말한 4가지 역할을 실제 화면 컨셉으로 보여준다 — 정상/위험/급변/판정보류 4개 카드.
- 사용 자료: 4-2절, `chart_mockup_dashboard.png`
- 발표 포인트: 화면 하단 "실제 배포된 소프트웨어 화면이 아님" 고지문을 발표 중에도 한 번 언급 — 목업이라는 점을 숨기지 않는 것 자체가 신뢰도를 준다.

**11. 작동 조건과 한계**
- 핵심 메시지: 언제 작동하는지(CN7, 특정 운전 구간 집중)와 언제 작동하지 않는지(부품별 결과가 갈릴 때, 동일 급변인데 결과가 다를 때, 사전예측, RG3, 불량 14그룹 중 11개가 한 연속 구간에 집중되어 있다는 표본 다양성 제약)를 한 화면에 나란히 제시. 한계는 프로젝트의 결함이 아니라 다음 데이터 요구사항으로 연결.
- 사용 자료: 7절, 8절 표, 15-3절
- 발표 포인트: 한계를 감추지 않고 "그래서 무엇이 더 필요한가"로 끝맺어 12번 슬라이드로 연결.

**12. 마무리 — 이 프로젝트의 핵심은 모델이 아니다**
- 핵심 메시지: "이 프로젝트는 모델 성능이 아니라, 제조 데이터의 구조에 맞는 AI 적용 범위를 찾아냈습니다. CN7에서는 공정 이상 구간 탐지, RG3에서는 판정 보류 및 데이터 개선으로 역할을 분리했습니다." 기대효과는 효과의 크기가 아니라 효과가 발생하는 경로(관찰 사실 → 적용 가능성 → 실제 효과는 향후 검증)로 제시. "하지 않는 주장" 목록을 작게라도 화면에 남긴다.
- 사용 자료: 0절 핵심 메시지, 6절, 8절 데이터 요구사항, 9절 심사기준 매핑(마지막 한 줄 요약용)
- 발표 포인트: 처음 1번 슬라이드의 "최종검사 전에 불량을 예측하자"는 문제의식과 이 슬라이드를 연결한다 — "그래서 최종검사를 대체하는 것이 아니라, 공정 중 이상 상태를 먼저 발견하고 검사 우선순위를 지원하도록 설계했다"는 문장으로 닫는다.
