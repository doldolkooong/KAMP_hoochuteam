# KAMP 사출성형 품질 위험 분석 — CN7 · RG3

사출성형 공정 데이터를 이용해 **최종검사 전에 확인할 공정 상태와 제품의 검사 우선순위**를 찾는 프로젝트입니다. 처음에는 센서값으로 개별 제품의 불량을 예측하려 했습니다. 데이터를 살펴보고 시간 순서로 검증하면서, 현재 자료로 확인할 수 있는 범위를 **품질 위험 신호와 모델의 불확실성 제시**로 좁혔습니다.

이 저장소에는 CN7과 RG3의 최종 실행 코드, 바탕화면에 있던 실험 노트북 전체, 모델과 결과 요약을 담았습니다. 원본 데이터와 큰 예측 파일은 포함하지 않습니다.

> **사용 범위:** 위험 점수나 OOD 경보는 불량 확정 판정이 아닙니다. 낮은 점수도 검사 면제 근거가 아닙니다. 두 제품 모두 기존 품질검사를 유지하면서 결과를 검사 순서와 추가 확인에 활용하도록 설계했습니다.

## 왜 문제를 다시 정의했나

최초 목표는 `PassOrFail`을 이용한 **부품 단위 정상·불량 예측**이었습니다. EDA 과정에서 동일한 23개 공정변수 조합에 정상과 불량이 함께 관측되는 경우를 발견했습니다. 불량이 나온 공정조건 그룹 중 한쪽 결과만 불량인 그룹은 CN7에서 11/14개, RG3에서 25/25개였습니다. 센서 입력만으로 그 그룹 안의 개별 부품을 구별하기 어렵다는 뜻입니다.

그래서 탐색 단계에서는 질문을 “이 부품이 불량인가?”에서 “**이 공정조건에서 불량이 관측되었는가?**”로 바꾸어 그룹 단위 분석도 수행했습니다. 여기서 그룹은 *23개 공정변수 값이 같은 관측치의 묶음*입니다. 실제 생산 `Shot_Number`가 없어 물리적인 한 샷과 일치하는지는 확인하지 못했습니다. 이 탐색 결과가 최종 모델의 부품별 판별 능력을 입증하는 것은 아닙니다.

두 제품의 불량 패턴도 달랐습니다. CN7 불량 공정조건 그룹 14개는 전체 606개 중 24~60번째의 짧은 구간에 몰렸고, RG3의 25개는 591개 중 넓은 범위에 흩어져 있었습니다. 따라서 같은 모델과 같은 판정 기준을 두 제품에 그대로 적용하지 않았습니다.

## 어떻게 현재 구조에 도달했나

| 단계 | 확인한 내용 | 최종 설계에 반영한 점 |
|---|---|---|
| 데이터 진단·복원 | 라벨, 시간, 제품 측면과 원본 행의 대응을 확인하고 중복 공정조건을 조사 | 공통 원본은 한 곳에 두고 제품별 전처리를 분리 |
| 초기 모델·특징 실험 | CN7은 특정 운전 구간을 구별했지만, RG3의 단순 공정값은 불량 구분이 불안정했음 | CN7은 시간 흐름 특징, RG3은 최근 상태에서 벗어난 정도를 사용 |
| 검증 방식 재점검 | CN7 내부 교차검증의 높은 점수가 미래 기간에도 유지되지 않았음. RG3도 세션별 편차가 컸음 | 내부 검증과 미래 시간 검증을 분리해 보고 |
| 실패 사례 분석 | CN7의 새 공정 이탈과 센서상 정상에 가까운 불량을 기존 분류기가 놓쳤음 | CN7에 PCA 기반 OOD 경보를 추가하고, 탐지하지 못하는 경우를 명시 |
| 활용 범위 결정 | 두 제품 모두 낮은 점수만으로 안전하게 검사를 생략할 근거가 없음 | 자동 합격·불합격 판정 대신 검사 우선순위와 모델 신뢰도 표시 |

탐색 과정의 상세 기록은 [분석 로그](docs/research/analysis_log.md)와 [프로젝트 구상](docs/research/project_idea.md)에 있습니다. 이 문서들은 중간 가설도 포함하므로, 실제 실행 모델과 재현 결과는 아래 제품별 코드와 결과 파일을 기준으로 봐야 합니다.

## 제품별 최종 접근

### CN7: 기존 위험 패턴 + 새로운 공정 이탈

CN7 학습 데이터는 1,211행(정상 1,194 / 불량 17)입니다. 최종 파이프라인은 23개 센서, RH/LH 정보, 직전 5개 사이클의 센서 평균을 합친 47개 특징으로 LightGBM 모델 5개를 학습합니다. 모델 사이 판단 차이는 불확실성 신호로 사용합니다.

미래 기간의 불량을 기존 위험 모델이 놓치는 사례를 확인한 뒤, **과거 정상 사이클에서 학습한 PCA 재구성 오차**로 학습 분포 밖의 공정 상태를 표시하는 OOD 계층을 더했습니다. OOD는 “평소와 다름”을 뜻하며 불량 여부를 확정하지 않습니다. 자세한 특징·임계값·운영 원칙은 [CN7 문서](cn7/README.md)에 있습니다.

### RG3: RH 위험 순위화, LH는 기존 검사

RG3 학습 데이터 1,182행 중 RH 591행에서 불량 25건이 관측됐고, LH에서는 관측된 불량이 없었습니다. 측면 정보만으로 답을 맞히는 모델을 피하기 위해 지도학습은 **RH 591행**으로 제한했습니다. 최근 생산 상태와 현재 값의 차이를 나타내는 `Absolute EWMA5` 특징 23개와 XGBoost를 사용합니다.

시간 순서에 따른 검증 결과가 세션마다 크게 달라 고정 임계값의 자동 판정을 적용하지 않았습니다. RH에는 상대적인 **위험 순위**를 제공하고, 불량 학습 사례가 없는 LH는 기존 검사를 유지합니다. 자세한 설정은 [RG3 문서](rg3/README.md)에 있습니다.

## 결과를 어떻게 읽어야 하나

| 제품·검증 | 결과 | 해석 |
|---|---|---|
| CN7 내부 반복 그룹 교차검증 | 5개 seed 평균 PR-AUC **0.8164 ± 0.0181** | 같은 개발 기간 안에서의 구분 결과. 미래 성능으로 해석하면 안 됨 |
| CN7 미래 기간 E4 (2020-10-27) | 위험 모델 PR-AUC **0.1156**; 위험 기준으로 불량 10행 모두 미탐 | 기존 위험 패턴이 새 기간에 일반화되지 않음 |
| CN7 E4의 PCA OOD, 사이클 기준 | 불량 5사이클 중 **4개 탐지**, 오경보 0개 | 기존 모델이 놓친 강한 공정 이탈을 사후 분석에서 포착 |
| CN7 미래 기간 E5 (2020-11-03) | 위험 모델 PR-AUC **0.0147**; OOD도 불량 1사이클 미탐 | 센서상 정상과 겹치는 불량은 여전히 놓칠 수 있음 |
| RG3 순차 세션 검증 | 세 fold PR-AUC **0.3395 / 0.0434 / 0.0735** | 생산 세션에 따라 성능 편차가 큼 |
| RG3 초기 holdout (세션 1~3 → 4~5) | PR-AUC **0.0383**; 해당 구간 불량률 **0.0400** | 이 구간에서 무작위 순위보다 낫다는 근거가 없음 |

CN7의 E4/E5 OOD 분석은 기존 모델의 실패를 본 뒤 수행한 **사후 보완 실험**입니다. 독립적인 최종 성능 검증으로 볼 수 없습니다. 위 값은 저장소의 [CN7 결과 요약](cn7/outputs/cn7_metrics.csv), [CN7 시간 검증](cn7/outputs/cn7_temporal_ood_side_results.csv), [RG3 시간 검증](rg3/outputs/rg3_temporal_validation.csv) 및 제품별 문서에 근거합니다. 실제 검사 시간 절감이나 불량 유출 감소 효과는 이 데이터로 측정하지 않았습니다.

## 실험 노트북: 시도한 과정까지 보존

바탕화면 `kamp`와 `final`에 있던 노트북 **88개를 전수 확인**했습니다. 내용이 완전히 같은 복사본 4개를 한 파일로 묶어 **고유 노트북 84개**를 보존했습니다. 이전 저장소에 이미 있던 공통 EDA·전처리 노트북 5개를 합하면 현재 저장소에는 **89개**가 있습니다.

| 분류 | 보존한 노트북 | 내용 |
|---|---:|---|
| [CN7](cn7/notebooks/) | 58개 | 로지스틱 회귀·트리 계열·불균형 처리·파생변수·SHAP·이상탐지·시간 검증, 재분석 12단계, 최종 분석 |
| [RG3](rg3/notebooks/) | 18개 | 기준 모델·샘플링·데이터/목표 변경·딥러닝 실험, 재분석 3단계, 최종 분석 |
| [공통 탐색](notebooks/exploration/) | 13개 | 데이터 탐색·EDA·전처리·복원 및 기존 저장소의 연습 노트북 |

제품별 `experiments/`에는 초기 시도를 번호 순서대로, `research/`에는 이후 재분석 단계를 두었습니다. 파일명은 영문으로 정리했지만 **셀의 코드·설명·실행 출력은 원본 그대로** 보존했습니다. 원래 파일명과 새 경로, 중복본의 대응 관계는 [노트북 전체 목록](docs/notebook_inventory.md)에서 확인할 수 있습니다.

과거 노트북에는 당시 바탕화면의 절대경로나 중간 CSV 경로가 남아 있을 수 있습니다. 이 노트북들은 실험 과정을 보여주는 기록이며, 새 저장소에서 바로 실행되는 최종 파이프라인은 아래 `run_*.py` 스크립트입니다.

## 저장소 구조

```text
.
├── data/raw/                 # CN7·RG3 공통 원본 CSV (Git 제외)
├── cn7/
│   ├── data/raw/             # CN7 전용 원본 CSV (Git 제외)
│   ├── data/processed/       # 전처리 결과 (Git 제외)
│   ├── notebooks/            # experiments / research / 최종 분석
│   ├── src/                  # 전처리·학습·검증·추론 코드
│   ├── models/               # 소형 최종 모델
│   ├── outputs/              # 결과 파일; 작은 요약만 Git 포함
│   └── run_cn7*.py
├── rg3/                      # 같은 data/notebooks/src/models/outputs 구분
│   └── run_rg3.py
├── notebooks/exploration/    # 초기 공통 EDA·전처리 노트북
├── docs/                     # reference / research / reports
├── requirements.txt
└── .gitignore
```

실험 노트북 일부는 Git에서 제외한 중간 CSV에 의존합니다. 결과 재현은 제품별 `run_*.py` 스크립트를 기준으로 합니다.

## 데이터 준비와 실행

원본 데이터의 크기와 공개 범위를 고려해 CSV는 Git에 올리지 않았습니다. 기존 바탕화면의 `final/CN7/data/raw/`, `final/RG3/data/raw/`에서 다음 파일을 **복사**해 배치합니다. 두 바탕화면 원본 폴더는 저장소 정리 과정에서 변경하지 않았습니다.

| 위치 | 필요한 파일 |
|---|---|
| `data/raw/` | `labeled_data.csv`, `unlabeled_data.csv` |
| `cn7/data/raw/` | `moldset_labeled_cn7.csv`, `moldset_unlabeled_cn7.csv` |
| `rg3/data/raw/` | `moldset_labeled_rg3.csv`, `moldset_unlabeled_rg3.csv` |

공통 `labeled_data.csv`와 `unlabeled_data.csv`는 한 번만 복사합니다. 데이터 사용·공개 범위는 KAMP 제공 조건을 확인하세요. Python 3.12에서 저장소 루트를 기준으로 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
cd cn7
python run_cn7.py
python run_cn7_temporal_ood.py
python run_cn7_test.py
cd ..\rg3
python run_rg3.py
```

RG3 테스트 추론에 필요한 `unlabeled_data.csv`가 없다면 `python run_rg3.py --skip-test`로 학습과 검증만 실행할 수 있습니다. 과거 분석 노트북용 복원 CSV와 실행 조건은 [CN7 문서](cn7/README.md), [RG3 문서](rg3/README.md)를 참고하세요.
